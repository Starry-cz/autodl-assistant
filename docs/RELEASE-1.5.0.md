# v1.5.0 检查与验证

本版整合响应速度优化、界面排版调整和稳定性修复。测试使用隔离账号、临时目录与合成库存，不以真实租用或开机验证成功率。

## 修复的问题

| 方面 | 问题与处理 |
| --- | --- |
| 稳定性 | 连续准备失败被中间成功读取清零，导致退避失效；现在只在完整成功轮次清零，人工恢复重新获得重试额度。 |
| 任务逻辑 | 人工恢复、绑定和重新核对的身份读取可能被后台导航打断；现在与任务共用页面锁，取消后的迟到请求不能恢复任务。 |
| 通知可靠性 | HTTP 200 后回执中断仍被误报成功；现在保留失败并退避重试，微信需明确的业务成功回执。 |
| 安装可用性 | 先运行源码版生成的登记文件阻挡默认在线安装；现在识别专用登记目录并保留原数据位置。 |
| 凭据与访问 | 继续使用本机请求限制、来源校验、本地令牌、Windows DPAPI 和账号归属隔离。发布包不包含本机会话或任务数据。 |
| 效率 | 到期调度去掉逐任务额外等待；多地区只读预筛最多并行两路，命中后取消并等待其余读取结束，付费操作保持串行。 |
| 可读性 | 统一标题、正文、说明的字号层级，压缩多余留白，保留监控图表比例、固定表头和窄屏布局。 |

## 性能测量范围

本机合成基准中，12 个同时到期任务全部开始所需时间由约 6131ms 降为 184ms；首地区慢、第二地区有卡时的预筛由约 1023ms 降为 217ms。第一地区立即有卡时基本没有收益，还会多一个预发的只读请求。全部批次结束时没有在途遗留读取。

这些是本地调度和预筛开销，不是完整抢卡耗时或成功率。复跑方法见 [性能验证](PERFORMANCE.md)。

## 验证边界

已验证的系统为 Windows 10 x64；Windows 11、ARM64、macOS 和 Linux 未做实机验证。EXE 未进行代码签名。安装包验证与“运行安装向导并修改注册表”是不同的测试，本次不会替换当前电脑已安装的软件。

官网的布局、接口、限流和库存可能变化；自动测试通过不能保证永远没有问题。当前工具面向单用户本地运行，付费提交结果不明时先核对，不通过重复提交或并发创建提高成功率。
