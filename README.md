# AutoDL 助手

本地运行的中文 AutoDL 工作台：查看 GPU 库存、创建抢卡任务、管理实例与账单。监控室与抢卡控制台在同一个程序中，不需要分别启动。

## 先选择一种使用方式

**普通用户推荐第 1 种。以下方式任选一种，不需要全部安装。** 桌面版和网页版连接 AutoDL 都需要联网，不要求电脑有独立显卡。

| 方式 | 打开形式 | 是否需要提前安装环境 | 适合谁 |
| --- | --- | --- | --- |
| [1. EXE 安装包](#method-1) | 独立桌面窗口 | 不需要，环境已打包 | 希望像普通软件一样使用 |
| [2. 便携 ZIP](#method-2) | 独立桌面窗口 | 不需要，环境已打包 | 不想安装，解压后直接运行 |
| [3. 下载源码后双击](#method-3) | 本机浏览器网页 | 不需要，首次自动准备 | 希望保留或修改源码 |
| [4. 单文件在线安装](#method-4) | 本机浏览器网页 | 不需要，首次自动下载 | 希望只下载一个小文件 |
| [5. 两条 PowerShell 命令](#method-5) | 本机浏览器网页 | 不需要，首次自动下载 | 希望用命令安装，或指定安装目录 |

本文下载链接对应 **v2.0.1**。第 1、2 种自带运行环境；第 3、4、5 种首次运行需要联网下载 Node.js（如本机缺少）、依赖和浏览器组件。它们不要求安装 Git。

**系统要求：**桌面包支持 Windows 10/11 x64；源码网页版提供 x64 / ARM64 环境下载路径。已在 Windows 10 x64 验证，未在 Windows 11 或 ARM64 实机验证；当前不提供 macOS、Linux 和 ARM64 桌面安装包。

<a id="method-1"></a>
## 1. EXE 安装包：像普通软件一样安装（推荐）

1. [下载 v2.0.1 桌面安装包](https://github.com/Starry-cz/autodl-assistant/releases/download/v2.0.1/autodl-assistant-desktop-2.0.1-setup-x64.exe)。文件名以 **setup-x64.exe** 结尾。
2. 下载完成后，双击这个 EXE。安装到当前 Windows 用户，不需要管理员权限，也不用安装 Node.js、npm 或浏览器环境。
3. 安装完成后，打开桌面的 **AutoDL助手桌面版**。也可以从 Windows 开始菜单找到同名程序。
4. 按下方[首次登录与使用](#first-use)连接 AutoDL，然后使用监控室或创建抢卡任务。
5. **以后启动：**双击 **AutoDL助手桌面版** 快捷方式。重复打开只会显示已有窗口。
6. **完全退出：**右键任务栏右下角的助手托盘图标，选择 **停止并退出**。窗口右上角 **×** 只是收进托盘，后台任务继续运行。

当前安装包未进行 Windows 代码签名，系统可能显示“未知发布者”。请核对文件来自本仓库的发布页，无需关闭系统防护。

<a id="method-2"></a>
## 2. 便携 ZIP：全部解压后直接运行

1. [下载 v2.0.1 完整便携包](https://github.com/Starry-cz/autodl-assistant/releases/download/v2.0.1/autodl-assistant-desktop-2.0.1-win-x64.zip)。文件名以 **win-x64.zip** 结尾。
2. 右键 ZIP，选择 **全部解压**，放到自己有写入权限的固定文件夹，例如 `D:\AutoDL桌面版`（有 D 盘时）。
3. 打开解压后的文件夹，双击 **AutoDL Assistant.exe**。这是完整桌面程序，不需要先安装 Node.js 或运行任何 CMD。
4. 按下方[首次登录与使用](#first-use)完成登录。
5. **以后启动：**仍然打开该文件夹中的 **AutoDL Assistant.exe**；也可自行创建它的桌面快捷方式。
6. **完全退出：**右键助手托盘图标，选择 **停止并退出**。点击窗口 **×** 只隐藏窗口。

**必须保留解压后的全部文件。** 不要在压缩包内直接运行，不要单独拖出 EXE。GitHub 发布页里的 **Source code (zip)** 是源码，不是这种包含环境的便携包。

“便携”指程序无需安装；账号与任务数据仍保存在本机 AppData，**不会随程序文件夹或 U 盘一起移动**。同一 Windows 用户的安装版与便携版共用桌面数据和单实例锁。

<a id="method-3"></a>
## 3. 源码网页版：下载源码，双击启动

1. [下载 v2.0.1 完整源码包](https://github.com/Starry-cz/autodl-assistant/releases/download/v2.0.1/autodl-assistant-v2.0.1.zip)。如果希望取得尚未发布的修改，也可在仓库主页选择 **Code → Download ZIP** 下载 `main` 分支；`main` 会持续变化，与固定版本包可能不同。
2. 右键 ZIP，选择 **全部解压**，放到有写入权限的固定目录，例如 `D:\AutoDL助手`。不要在 ZIP 内运行。
3. 进入项目目录，确认同一层能看到 **package.json、public、src、scripts、启动抢卡助手.cmd**。若只看到一个项目文件夹，继续打开这一层。
4. 双击 **启动抢卡助手.cmd**。首次会依次准备运行环境、安装依赖、检查浏览器，再启动后台。保持联网并等待“启动成功”，不要在下载途中关闭窗口。
5. 浏览器会自动打开 [http://127.0.0.1:8787](http://127.0.0.1:8787)。如没有自动打开，在浏览器地址栏输入这个地址，再按下方[首次登录与使用](#first-use)操作。
6. **以后启动：**双击同一目录中的 **启动抢卡助手.cmd**，无需重复解压或安装。该方式不会自动创建桌面快捷方式，可自行给这个 CMD 创建快捷方式。
7. **完全退出：**双击同一目录中的 **停止抢卡助手.cmd**，等待停止完成。关闭浏览器标签页不会停止后台任务。

无需手动安装 Node.js：启动器会复用可用的 Node.js 22+，缺少时将 Node.js 22.23.4 下载到项目 `.tools`。浏览器会优先使用已有可用组件，缺少时下载 Chromium；不修改系统或用户 PATH。

源码里的 **安装并启动.cmd** 在完整项目中也会调用同一个启动器；它用于安装引导，日常只需记住 **启动抢卡助手.cmd**。源码启动打开的是网页，不是 Electron 桌面窗口。

<a id="method-4"></a>
## 4. 单文件在线安装：只下载一个 CMD

1. [下载 v2.0.1 在线安装启动器](https://github.com/Starry-cz/autodl-assistant/releases/download/v2.0.1/autodl-assistant-setup.cmd)。这是一个小的安装引导文件，**不是离线安装包**。
2. 双击 **autodl-assistant-setup.cmd**，保持联网。它会下载完整源码，再自动准备环境并启动网页版。
3. 默认安装位置是 `%LOCALAPPDATA%\AutoDL-Assistant`。可将这个路径粘贴到资源管理器地址栏查看。
4. 等待“安装和启动完成”。浏览器会打开 [http://127.0.0.1:8787](http://127.0.0.1:8787)，随后按[首次登录与使用](#first-use)连接账号。
5. **以后启动：**使用桌面上的 **AutoDL助手** 快捷方式，或进入安装目录双击 **启动抢卡助手.cmd**。此处的快捷方式名字没有“桌面版”三个字，打开的是浏览器网页。
6. **完全退出：**进入安装目录，双击 **停止抢卡助手.cmd**。仅关闭网页不停止后台。

安装器不会覆盖已有同名桌面快捷方式。若未生成快捷方式，或原快捷方式指向另一目录，直接使用本次安装目录里的 **启动抢卡助手.cmd**。

默认目录已有本项目旧版时，安装器保留原数据并准备新版，成功后切换启动入口；遇到无关文件或其他安装占用端口时会停止并说明原因。更换程序保存位置可使用第 5 种方式指定目录；同一用户的默认网页版入口会继续使用已登记的数据目录。

<a id="method-5"></a>
## 5. PowerShell 安装：复制两条命令

这与第 4 种安装的是同一份网页版，也不需要提前安装 Node.js、npm 或 Git。

1. 按 **Win + R**，输入 `powershell`，按回车。使用普通窗口即可，不需要“以管理员身份运行”。
2. 先粘贴下面第一条命令，按回车，等待下载结束：

```powershell
Invoke-WebRequest -UseBasicParsing -Uri "https://raw.githubusercontent.com/Starry-cz/autodl-assistant/v2.0.1/install.ps1" -OutFile "$env:TEMP\install-autodl.ps1"
```

3. 再粘贴下面第二条命令，按回车，等待安装和启动完成：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\install-autodl.ps1"
```

4. 默认安装到 `%LOCALAPPDATA%\AutoDL-Assistant`，浏览器自动打开 [http://127.0.0.1:8787](http://127.0.0.1:8787)。按[首次登录与使用](#first-use)连接账号。
5. **以后启动：**使用桌面 **AutoDL助手** 快捷方式，或安装目录中的 **启动抢卡助手.cmd**，不必每次再运行两条命令。
6. **完全退出：**双击安装目录中的 **停止抢卡助手.cmd**。

如需自定义安装目录，**第 3 步改用下面这一条**，例如安装到空的 `D:\AutoDL助手`（需有 D 盘）：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File "$env:TEMP\install-autodl.ps1" -InstallDir "D:\AutoDL助手"
```

请在 PowerShell 中执行，不能粘贴到浏览器地址栏、CMD 或 Node.js 交互窗口。首次下载失败时保留报错，网络恢复后重试；若源码已下载到安装目录，直接运行其中的 **启动抢卡助手.cmd** 即可。

<a id="first-use"></a>
## 首次登录与使用（五种方式通用）

1. 打开助手，点击左下角头像，在菜单选择 **账号设置**，再点击 **打开登录**。
2. 在打开的 AutoDL 官网专用窗口里自行登录。普通浏览器已登录，不代表助手的专用窗口已经登录；密码和验证码在官网填写。
3. 助手会尝试自动核验。若没有自动连接，回到 **账号设置** 点击 **检查登录状态**。确认成功后，登录窗口转入后台，助手按顺序同步实例、账单和 GPU 目录；部分同步失败可点击 **同步账号内容** 重试。
4. 点击设置侧栏的 **返回工作台**，在 **监控室** 查看库存，选择刷新间隔、开始或暂停跟踪。点击型号、地区或热力图格子，可筛选下方主机明细；**用于抢卡** 只填写条件，不会直接租用。
5. 进入 **抢卡控制台**，选择下面三种任务之一，填写必要配置：

| 任务模式 | 需要选择 | 自动执行时的行为 |
| --- | --- | --- |
| 新租服务器 | 地区、GPU 型号与卡数；同步官方镜像后依次选择框架、版本、Python、CUDA | 创建新实例并开机 |
| 已有实例开机 | 已同步目标实例；无卡运行的实例需先在官网关机 | 等待原主机有空卡后开机；已开机或开机中则核对结果，沿用原实例配置和计费方式 |
| 同地区克隆 | 已关机源实例、目标 GPU、是否复制数据盘 | 在源实例同地区克隆并开机，保留原实例 |

6. 选择 **仅提醒** 或 **自动执行**，设置检查间隔和最长监测时间。仅提醒发现资源后通知并停止，不租用或开机；自动执行需要勾选费用授权。
7. 启动任务后，在右侧队列查看状态、检查次数与倒计时。**详情与日志** 内可查看采样、导出日志，以及暂停、恢复、停止任务。提交结果待核对时按提示处理，不要反复建立同一任务。
8. 在 **我的实例** 查看配置与运行状态。点击左下角头像可进入 **账单** 或 **软件更新**；通知渠道在设置中心的 **通知** 中配置。AI 选卡、开发者 Token 余额保护、Webhook 和微信通知均为可选功能，不是首次启动的前提。

**监控室的“自动跟踪”和抢卡任务不是一回事：**切到助手内的其他页会暂停看板自动刷新，抢卡任务仍由后台持续检查。网页版切到后台标签或关闭网页后不再自动刷新看板；桌面版停留在监控室时，收进托盘仍可继续跟踪。关闭网页版后，浏览器桌面提醒不会弹出，消息会保留；已配置的后台通知按任务设置发送。

## 工作台与设置入口

工作台侧栏用于切换 **监控室、抢卡控制台、我的实例、消息中心、AI 选卡**。点击左下角头像，菜单提供 **账号设置、账单、软件更新、退出 AutoDL**。

进入账号设置、账单或软件更新后，侧栏会切换为设置中心：

| 设置页面 | 可以做什么 |
| --- | --- |
| 账号设置 | 连接 AutoDL、检查登录、同步账号内容 |
| 通知 | 配置 Webhook 和 AutoDL 微信通知 |
| 账单 | 查看消费走势、近期流水、余额和余额凭据 |
| 软件更新 | 查看版本、检查和安装更新，以及本机运行状态 |

点击设置侧栏顶部的 **返回工作台**，会回到最近使用的工作页面。页面切换会同步到地址栏，浏览器的后退、前进也可以在已访问页面间切换。

### 测试微信或 Webhook 通知

1. 点击左下角头像 → **账号设置** → 设置侧栏的 **通知**。
2. 启用所需渠道并填好配置。微信需要先在 AutoDL 绑定微信，并填写开发者 Token；Webhook 需要支持本程序消息格式的 HTTPS 接收地址，Bearer Token 按接收服务要求填写。
3. 点击 **保存通知设置**。页面还有未保存修改时，测试按钮不可用。
4. 点击对应渠道的 **发送测试通知**。按钮下方会显示发送时间、成功结果或失败原因；微信成功表示 AutoDL 已接受请求，还需在手机微信确认收到。
5. 失败时按提示检查 Token、微信绑定、接收地址或网络。测试不会创建抢卡任务，也不会自动重试；微信测试与任务提醒共用发送限额，限速时按提示等待再试。

Webhook 以 JSON POST 发送 `id`、`event`、`title`、`name`、`content`、`taskId` 和 `timestamp`，并带有 `Idempotency-Key`。测试消息的 `event` 为 `test`、`taskId` 为 `null`；接收服务应允许该测试类型。

## 版本检查与更新

1. 点击左下角头像，选择 **软件更新**，进入独立更新页，查看当前版本、最新正式版本和本机运行状态。无需登录 AutoDL 即可检查。打开助手后自动检查，持续使用时约每 6 小时再检查；也可点击 **检查更新**。
2. 有新版时，左下角账号入口显示 **有新版本**。查看更新说明后，点击 **更新并重启**；五种安装方式都使用这个入口。
3. 程序先下载到独立目录并检查运行环境，原后台在准备期间继续运行。准备完成后正常关闭旧后台，启动新版；网页自动刷新，桌面窗口重新打开。不要在此期间手动删除旧程序或数据目录。
4. 原登录资料、任务、配置和日志继续使用原数据目录。会话仍有效时自动恢复连接；原监测任务按原截止时间继续，暂停任务保持暂停。会话过期或任务需要人工核对时，按页面提示处理，不会自动重新下单。

提交、配置核对或结果确认期间会拒绝切换；任务进入稳定状态后可重试。下载或环境准备失败时旧后台继续运行，错误会显示在更新区域。交接后新版无法就绪时保留原程序和数据；只有确认新版进程已经结束，才允许回到旧版，避免两个进程同时使用账号资料。

| 原使用方式 | 自动更新后的程序位置与入口 |
| --- | --- |
| EXE 安装版、便携 ZIP | 新程序放在桌面用户数据目录的 `updates` 子目录；继续使用本版的原快捷方式或 EXE，会转到已验证的新版本。Windows“已安装应用”中的登记版本可能仍是初装版本，以助手页面的当前版本为准。 |
| 源码双击、单文件在线安装、PowerShell 安装 | 新程序与原数据分开存放；继续使用本版启动入口，会转到成功更新的版本。原 `.runtime` 不搬移、不清空。 |

**手动安装**仍可用：先停止任务并完全退出旧程序，再安装新版 EXE。网页用户建议运行新版在线安装器并将 `-InstallDir` 指向原安装目录。同一 Windows 用户通过默认端口 `8787` 打开新版源码时，也会沿用已登记的网页版数据；程序存放位置与数据位置可以不同。

网络失败时会显示检查失败，不会把它当作“已是最新版”；自动检查稍后重试，手动检查至少间隔 1 分钟。检查仅访问本仓库的公开发布信息，不需要 GitHub Token，也不发送 AutoDL 账号或任务内容。

**自动切换从 v1.3.0 起提供；v1.2.1 及以前需先手动升级到本版一次。** 桌面用户先从托盘完全退出旧版，再安装本版 EXE 或解压本版便携包并运行新 EXE；后续使用这个新入口。网页用户运行上面的新版安装器，指定原安装目录，可保留原 `.runtime`。网页安装器会在成功后升级原目录的启停脚本，让原快捷方式继续可用；未经过升级的旧副本不会自行获得新功能。

## 停止、数据与升级

| 你使用的方式 | 本地数据位置 | 完全停止方式 |
| --- | --- | --- |
| 第 1、2 种桌面版 | `%APPDATA%\AutoDL Assistant Desktop\runtime` | 托盘菜单 **停止并退出** |
| 第 3 种源码网页版 | 该项目目录下的 `.runtime` | 项目里的 **停止抢卡助手.cmd** |
| 第 4、5 种在线安装网页版 | 默认 `%LOCALAPPDATA%\AutoDL-Assistant\.runtime`；自定义时在对应安装目录下 | 安装目录里的 **停止抢卡助手.cmd** |

- 电脑需要保持联网和唤醒。**停止监测、退出程序、关闭电脑都不会替你关闭云端实例**；已开机资源仍需到 AutoDL 控制台关机，扩容数据盘在关机后仍可能计费。
- 日常升级优先进入 **软件更新**，点击 **更新并重启**，同一使用形式继续使用原数据目录；手动安装与首次升级步骤见上节。
- 网页自动升级后的程序放在安装目录的 `.versions` 中，原 `.runtime` 继续保留；不要删除原安装目录或只移动其中一个子目录。
- 桌面版与网页版数据相互独立。网页版第 3～5 种使用方式在同一用户、默认端口下复用已登记数据；如需独立测试副本，须同时设置不同的 `PORT` 和 `AUTODL_RUNTIME_DIR`。换电脑后重新登录，本地历史和可选凭据不会自动迁移。
- 登录资料和可选凭据只存本机；记住凭据时使用当前 Windows 用户保护。不要上传或分享 `.runtime` / `runtime`。
- 重新打开后先检查登录与任务状态；程序启动不等于原任务自动恢复。头像菜单的 **退出 AutoDL** 会退出本项目的专用登录，与退出本地程序是两个操作。

## 常见问题

| 问题 | 处理方法 |
| --- | --- |
| 不会安装 Node.js | 普通用户无需手动安装。桌面包已内置；网页启动器在需要时自动下载。 |
| ZIP 解压后没有 `AutoDL Assistant.exe` | 检查下载类型：便携包才有 EXE；源码包运行 `启动抢卡助手.cmd`。 |
| 双击 EXE 提示缺文件 | 重新完整解压，不要只复制 EXE，也不要在压缩包里运行。 |
| 第一次启动很慢 | 第 3～5 种需要下载环境与依赖，等待窗口步骤完成。需能访问 GitHub、nodejs.org、npm 和浏览器下载服务。 |
| 浏览器没有自动打开 | 网页后台提示成功后，手动打开 `http://127.0.0.1:8787`。桌面版直接使用桌面窗口，无需输入这个地址。 |
| 提示后台仍在使用旧代码 | 运行本版启动器会先准备环境，再正常切换同一数据目录的旧后台；提交或结果核对期间先处理任务。仅刷新网页不会更新后台。 |
| 提示端口被另一目录占用 | 先从另一份网页安装目录停止后台，再启动本目录。显式指定了另一数据目录时不会自动接管；默认网页版更新沿用已登记的数据。 |
| 安装器提示目录不为空 | 本项目旧版可升级；无关非空目录不会覆盖。核对路径或指定空目录，不要删除账号数据。 |
| 关闭后找不到桌面窗口 | 查看右下角系统托盘（包括隐藏图标），点击助手图标或再次打开快捷方式。 |
| 找不到版本更新入口 | v1.1.1 及之前需先手动升级到本版；新版本入口在左下角头像菜单的 **软件更新**。 |
| 有检查更新但没有“更新并重启” | v1.2.0 / v1.2.1 仅支持检查和手动下载；先升级到本版一次。 |
| 官网已登录，助手仍提示未连接 | 在 **账号设置** 打开专用登录窗口并检查登录状态；验证码由你在官网完成。 |
| 页面只有“—”或数据未同步 | 先连接账号，再同步。未知数据不会当作 0；分页未读完整时会提示。 |

## 功能与使用范围

- **监控室：**库存概览、型号和地区分布、空闲趋势、热力图、主机明细及条件联动。
- **抢卡控制台：**新租、原实例开机和同地区克隆，支持仅提醒、自动执行、任务控制及日志。
- **我的实例与账单：**实例搜索、运行状态、配置详情、官方管理入口、消费走势、流水和余额。
- **消息与 AI：**站内消息、桌面提醒、可选外部通知，以及规则或模型辅助选卡；模型建议需由你确认。

当前支持普通容器实例，不支持 `pro-...` 容器实例 Pro。可选地区为北京 B、西北 B、重庆 A、内蒙 B、北京 A、佛山，镜像使用官方公共基础镜像。页面接口或布局变化可能需要更新适配器。

库存、指标和账单均为同步时的快照，抢卡结果取决于库存、网络及平台响应。新租与克隆按提交时的 AutoDL 报价执行，预览不锁价；克隆开机与数据复制分别核验，GPU 运行不代表数据复制已完成。

## 项目结构与开发

| 目录 / 文件 | 职责 |
| --- | --- |
| `public/` | 原生 HTML、CSS、JavaScript 页面，通过本地 HTTP 接口读取状态和提交操作 |
| `src/server.mjs` | Node.js 本地 HTTP 服务、账号范围与操作入口 |
| `src/engine.mjs` | 任务状态、库存轮询、费用核对、执行与提交结果核对 |
| `src/adapters/` | Playwright 专用浏览器会话、AutoDL 页面读取与交互 |
| `src/store.mjs`、`credentials.mjs` | 本地数据落盘、重启恢复与 Windows 凭据保护 |
| `desktop/` | Electron 窗口、托盘、独立本地服务和桌面打包配置 |
| `scripts/`、根目录 CMD | 环境准备、启动/停止、打包和验收入口 |
| `tests/` | 使用隔离目录与合成数据的自动测试 |

桌面和网页共用同一套业务后端。界面请求进入本地服务后，由任务引擎和浏览器适配器执行；网页状态轮询读取本地状态，库存同步与云端操作按需进入专用浏览器，避免多个操作同时修改同一页面。任务状态和关键提交记录写入本地文件，提交结果不明确时先核对。

普通使用不需要执行下面的开发命令。开发时安装 Node.js 22.12+（含 npm），在包含 `package.json` 的目录打开 PowerShell：

```powershell
npm.cmd ci
npm.cmd test
npm.cmd run check
npm.cmd run test:workspace-ui
npm.cmd run test:market-ui
```

后台性能对比可运行 `node scripts/performance-benchmark.mjs` 和 `node scripts/inventory-prefilter-benchmark.mjs`；并行取消的浏览器验收运行 `npm.cmd run test:parallel-inventory`。三者使用离线合成数据；路径说明、测量范围与结果见 [性能验证](docs/PERFORMANCE.md)。

手动运行网页版：先执行 `npm.cmd run browser:install` 准备浏览器，再用 `npm.cmd start` 启动；打开 `http://127.0.0.1:8787`。在启动终端按 Ctrl+C，或另开终端运行 `npm.cmd run stop` 正常停止。

桌面调试默认与已安装桌面版共用 AppData，建议先为调试指定独立目录，再启动：

```powershell
$env:AUTODL_DESKTOP_DATA_DIR = Join-Path $env:TEMP 'AutoDL-Assistant-Dev'
npm.cmd run desktop:dev
```

Windows x64 打包使用 `npm.cmd run desktop:build`，产物位于 `output/desktop`。从源码构建需要联网下载依赖和配套浏览器；分发的完整桌面包已包含这些环境。
